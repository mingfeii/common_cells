# 配套代码接口与集成

所有生产模块位于 `rtl/`，使用可综合 SystemVerilog 子集，无厂商 IP 依赖。仿真检查和 `$fatal` 参数保护用 synthesis translate_off/on 包围。综合工具需要支持寄存器数组和属性；目标器件映射、时序和 CDC 签核由具体工程完成。

## 公共约定

- 所有信号在对应接口时钟的上升沿采样。
- `*_rst_n` 是低有效、异步断言、本地同步释放的复位。
- 双时钟模块的两个本地复位必须来自同一个共同异步复位，禁止独立清零某一侧。
- `valid && ready` 是唯一的接受/消费条件。valid 等待期间保持数据。
- `WIDTH>=1`，`STAGES>=2`。增加 STAGES 会增加同步延迟，不改变事务接口。
- FIFO 的 `rdata` 仅在 `rvalid=1` 时有效；不复位内存，所以空时可能为 X。

## 模块与接口

| 文件 | 参数 | 输入 | 输出 |
| --- | --- | --- | --- |
| [cdc_reset_sync](../rtl/cdc_reset_sync.sv) | STAGES=2 | clk，arst_n | rst_n |
| [cdc_sync_bits](../rtl/cdc_sync_bits.sv) | WIDTH=1，STAGES=2 | dst_clk，dst_rst_n，async_i | sync_o |
| [cdc_pulse_handshake](../rtl/cdc_pulse_handshake.sv) | STAGES=2 | src_clk，src_rst_n，src_valid；dst_clk，dst_rst_n | src_ready；dst_pulse |
| [cdc_mcp_handshake](../rtl/cdc_mcp_handshake.sv) | WIDTH=8，STAGES=2 | 源侧 src_data/src_valid；目的侧 dst_ready；两域时钟/复位 | 源侧 src_ready；目的侧 dst_data/dst_valid |
| [cdc_gray_counter](../rtl/cdc_gray_counter.sv) | WIDTH=8，STAGES=2 | 源侧 src_inc；两域时钟/复位 | src_bin/src_gray；dst_bin/dst_gray |
| [cdc_fifo_1deep](../rtl/cdc_fifo_1deep.sv) | WIDTH=8，STAGES=2 | 写侧 wdata/wvalid；读侧 rready；两域时钟/复位 | 写侧 wready；读侧 rdata/rvalid |
| [cdc_async_fifo](../rtl/cdc_async_fifo.sv) | WIDTH=8，ADDR_WIDTH=3，STAGES=2 | 同上 | 同上 |

`src_data/dst_data`、`wdata/rdata` 和计数器数据的宽度均为 WIDTH。`src_inc`、valid、ready、pulse 都为单 bit。

### cdc_sync_bits

WIDTH=1 用于状态电平。WIDTH>1 只适用于独立状态位或寄存后的 Gray 码，并需要符合对应协议/物理约束。它不保证普通总线的原子性。该模块只包含接收域同步器，源端寄存由调用者完成。

### cdc_pulse_handshake

每次源握手产生一个目的周期的 `dst_pulse`。目的端无背压接口，必须接收所有脉冲。握手忙时，源端 valid 可以保持等待；短暂拉高但没等到 ready 的请求没有被接受。

### cdc_mcp_handshake

单笔在途，目的输出有寄存器。首次看到同步请求后捕获数据并置 valid，下游实际消费后才发 ACK。源端等待 ACK 回传后才可覆盖保持寄存器。

### cdc_gray_counter

`src_inc=1` 每个源周期加一，`src_inc=0` 保持。计数自然回绕。`src_bin/src_gray` 为源域寄存器输出；`dst_gray` 为同步后 Gray；`dst_bin` 为对该 Gray 的组合解码，供目的同步逻辑采样。

### cdc_fifo_1deep

物理两个存储字，逻辑容量一个字。接受第一笔后，必须等其被读出且读指针同步回写域，才能再接受下一笔。低容量换取简单的单 bit 指针控制。

### cdc_async_fifo

容量严格为 `2^ADDR_WIDTH`，ADDR_WIDTH 至少为 1。读写可以在不同速率下连续发生。本实现比较当前指针判断空满，采用异步读 FWFT 接口。与单笔 FIFO 相比，它可以在下游未消费时继续接受数据，直到整个队列填满。

## 完整集成例子

[`cdc_mailbox_example.sv`](../examples/cdc_mailbox_example.sv) 是完整可综合顶层，默认 32 bit。它实例化两个本地复位同步器，再接入 MCP 邮箱。五组回归中的 MCP 测试直接实例化这个顶层，因此其连接也经过编译和事务自检。

使用时，模块外的源业务逻辑由 src_clk 驱动，目的业务逻辑由 dst_clk 驱动。外部业务逻辑也应使用与本域一致的同步释放复位策略。系统公共复位应满足目标单元最小复位脉宽，并能够可靠到达两个域。

参数连接建议显式写出 WIDTH/STAGES；特别是单 bit 内部同步器使用显式 WIDTH=1，避免仿真器全局 generic/parameter 覆盖造成意外位宽变化。运行脚本已使用顶层限定参数路径。

## 编译依赖

底层先编译 `cdc_reset_sync.sv`、`cdc_sync_bits.sv`，其余模块依赖 `cdc_sync_bits`。顶层例子依赖复位同步器与 MCP 模块。Questa 在 elaboration 阶段解析模块，随附脚本可以统一编译整个目录。

推荐把整套 7 个 RTL 文件加入工程，在业务需要处只实例化目标模块。未使用模块不会产生硬件。可综合代码没有等待、随机数或仿真时钟；这些仅存在于 sim 目录。
