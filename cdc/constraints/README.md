# CDC 物理约束与验收

本目录说明配套 RTL 的实现条件。由于没有指定目标工艺、时钟范围、STA 工具和综合网表，本目录不包含带假实例名的可执行 SDC。以下是集成时必须落实的路径和预算，不能把 RTL 自检通过当成这些条件已满足。

## 1. 同步器控制路径

所有 `cdc_sync_bits` 的 `pipe[0]` 是异步入口，`pipe[1]` 起是本地同步链。识别首级寄存器 D 引脚后，仅对真正异步的入口建立相位检查例外。一级到二级及后续级保留正常 setup/hold 分析。

对级间布线采用紧凑布局，并使用实际库/器件的同步器 MTBF 工具检查恢复时间。`ASYNC_REG`、`SHREG_EXTRACT` 是否识别取决于工具；ASIC 应映射合适的单元及布局策略，不能依赖 FPGA 属性字符串。

## 2. Gray 总线路径

起点是 `src_gray` 或 FIFO 的 `wgray/rgray` 寄存器 Q；终点是对端同步器第一级 D。要求物理延迟与位间偏斜不会使相邻源更新在接收端错误重叠。

一种保守实施方案是：分别按每个方向的最短源更新间隔，设置带裕量的最大数据路径延迟，并在支持时增加总线 skew 约束。源端每时钟可能加 1 时，该更新间隔就是最短源周期。考虑变频和时钟容差，不能只用典型周期。

首级至第二级不属于 Gray 跨域布线例外，应照常分析。

## 3. MCP bundled-data

起点为 `cdc_mcp_handshake.hold_data` 寄存器，终点为 `dst_data` 捕获寄存器。该路径没有逐位同步器。

`STAGES=2` 的最早捕获沿在 request 最初能被采到的目的沿之后两个目的周期。一个容易验收的保守预算是将完整数据建立路径控制在小于一个最短目的周期的范围内，并扣除不确定性与必要裕量。

预算必须明确是 Q 到 D 的布线/组合延迟，还是包含 clock-to-Q 的启动至建立总时间，再将 setup、时钟偏差及不确定性正确计入。不能只在文档写“给了两拍”，而不检查实际路径。

## 4. 异步读 FIFO 数据路径

`cdc_fifo_1deep` 和 `cdc_async_fifo` 的数据由存储寄存器经过读选择器到模块外的目的消费寄存器，路径终点不在本模块的 `rdata` 端口结束。预算应覆盖存储输出、选择器、模块间布线以及目的寄存器 setup。

写指针经过 STAGES 级同步后才让 `rvalid` 有效，目的端在随后合法读沿消费。可以按小于一个最短读周期的保守路径预算实施，前提是根据综合网表确认实际路径和约束覆盖。

## 5. 例外优先级与交付报告

对于上述需保留最大延迟预算的路径，不得让全局 asynchronous clock group 或 false-path 例外覆盖预算。按照所用工具的文档检查 timing exception 优先级；必要时使用针对单独入口的例外，而非一刀切整对时钟。

验收至少应获得：

- 每条同步链的首级和后续级匹配清单，匹配数不为零。
- 同步器级间 setup/hold 与恢复时间/MTBF 报告。
- 两个方向 Gray 总线的最差延迟与 skew 报告。
- MCP 和 FIFO 实际 bundled-data 起止点、预算及最差路径报告。
- 生效例外报告，确认不存在遮蔽预算的高优先级 false path。
- CDC/RDC 结构检查及对有意 bundled-data 路径的逐条解释。

本文使用的保守预算是可选择的实现策略，最终数值必须由项目时钟、器件和布局能力确定。它们不是原论文直接提供的目标平台 SDC。
